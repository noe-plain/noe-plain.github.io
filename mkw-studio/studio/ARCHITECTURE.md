# MKW Studio engineering boundaries

The application runs on static GitHub Pages. Runtime assets are bundled and committed; users install nothing and no project content is sent to a server. The optional Python server only adds image conversion (including TIFF/EXIF).

## Source and release

`build/editor-manifest.json` defines first-party module and stylesheet order. `npm run build` creates `static/editor.bundle.js`, its source map and `static/editor.bundle.css`, then versions runtime URLs by content. Vendor libraries are separate local files. Do not edit generated bundles. Source files are formatted with Prettier; the legacy editor globals remain a compatibility boundary inside the browser, rather than pretending these are independent ES modules.

## Persistence contract

A document has a stable `projectId`. A browser record has a monotonically increasing `version`. Saves compare the loaded version inside the same read/write transaction. A stale writer gets a new conflict-copy identity and no disk-file link. New projects receive separate records. The browser retains at most five projects, ordered by last successful save; the current save always survives retention. Older records and their exclusively owned assets are removed in the same transaction. Existing over-limit libraries are reduced when the database connection opens. Device MKW files are never deleted. A stale tab whose record was evicted gets a new recovery-copy identity and loses its disk-file link before autosave. Opening a project and its referenced blobs uses one read transaction, so garbage collection cannot race with reads.

IndexedDB stores image/font/logo bytes once by SHA-256; project records contain references. Saving/deleting a project collects assets unused across **all** records. Undo history and clipboard are session-only and do not enter portable files. Deleting a live object prunes unused live images; undo/clipboard retain what they need separately. Hidden objects still own their assets. The MKW payload remains version 1 with `assetFormat: 2`. Download-only files wrap this JSON payload in lossless native gzip; old uncompressed JSON files remain readable. `project-file.js` streams one asset at a time through compression/decompression, never serializing or parsing a whole multi-image project string. This avoids the engine string-length limit and removes most base64 file overhead without touching image pixels. No additional runtime library is needed. Corrupt/truncated gzip rejects before a document is restored. Native linked files use `project-blocks.js`: a 24-byte MKWBLK1 header locates a bounded gzip index after immutable, SHA-256-addressed raw binary assets. Layout saves replace only the index/header; additions overwrite the old index and append new blocks. Unchanged documents skip disk writes entirely. Removing/replacing any referenced asset compacts the file atomically, reusing file slices for retained bytes; no old layouts or deleted assets accumulate. Initial writes reuse IndexedDB blobs where available, avoiding another main-thread base64 conversion. All readers accept legacy JSON, monolithic gzip and the native block container. Block offsets, contiguous ranges, references and per-asset hashes are validated before restore. `file-io.js` applies prepared plans with an exclusive atomic writable stream, truncates the old tail and aborts on failure. `keepExistingData` still permits a browser-internal temporary full copy, so partial application writes are not a promise of physical in-place OS writes. Session version, revision and file-stamp checks run before planning and again before writing. Only one full-resolution normalized lossless PNG is written per used image, not an additional raw input copy. Used fonts are portable; the device font library stays outside the document.

A linked local file is updated only after the browser save attempt and the stored version check. If browser quota is exhausted, an explicit file save/download remains possible; the UI clearly reports the failed browser backup. Autosave never downloads a file. File handles are not exported. Permission is requested only during a user action; autosave only checks existing permission. External size/mtime changes block disk writes. `navigator.locks` serializes participating tabs. Browsers without file access use browser autosave plus explicitly initiated downloads; silent overwrites are impossible there.

## Path transform geometry

Stored path frames still define the coordinate system for control points and paints. Selection, sizing fields, snapping and group transforms derive tight geometric bounds with exact cubic extrema. Keeping these separate preserves existing paths and image/gradient fills when opening old projects. Do not replace the stored frame with control-handle extents or re-normalize it on selection.

## Text alignment

Carousel text has a `textAlign` default (`left`, `center`, `right`) and optional per-paragraph `textStyles[].align` overrides. Old documents omit both and remain left aligned. The text layout owns each line's measured width and left origin; canvas, inline editing, PDF selection text and PSD use that same origin. New paragraphs inherit size and alignment, not custom leading. Justification is a fourth alignment (`justify`) with word/letter/glyph distribution in the shared measured layout; it is not a fourth line-origin offset. See Bounded justification below.

## Export fidelity

All image, PDF and PSD export canvases are created with `exportContext` (sRGB, `willReadFrequently: true`) before their first drawing operation. Firefox's accelerated canvas readback can silently omit large photos even when the editor renders them correctly; the export context uses the CPU readback path. Photo loading validates successful load and nonzero intrinsic dimensions, and per-slide rendering skips photo frames outside that slide (including custom frame vertices). Original image data and resolution stay unchanged. Temporary image/PDF canvases are released even on encoding or decoding failure.

Canvas previews and image downloads share encoded bytes. PDFs use pdf-lib/fontkit: the rendered page preserves the artwork and an invisible embedded-font text layer enables search/selection. This is not an editable vector PDF. PSD preserves editable text, slide slices and native solid-fill/stroke Bézier paths. Complex image/gradient path paints retain exact raster appearance plus a disabled editable vector mask, labelled in the layer name. Photoshop behaviour and font substitution cannot be validated by the ag-psd round trip alone.

## Validation

`npm test` checks naming, calendar dates, layout, palette, asset references. `npm run test:browser` serves the committed production build on an ephemeral port and runs isolated Chromium suites. `CHROME_PATH` optionally selects a browser; macOS can use installed Chrome, CI installs Playwright Chromium. `MKW_TEST_OUTPUT` selects screenshot/export output. CI runs unit, formatting, reproducible-build and browser checks on pushes/PRs touching the app. Existing legacy Python/Photoshop scripts remain separate manual checks.

## Interactive performance

Single-post previews paint only visible boards plus a 200 px scroll-ahead margin. Their cache keys include document revision, board geometry, view resolution, edit state and loaded fonts; scrolling schedules newly visible work. Exports always render full resolution independently. Carousel pointer bursts are coalesced per animation frame, with the final queued position flushed before release and discarded on cancellation.

The start screen reads only the last project record, not its image blobs. Full assets are loaded when continuing. Linked-file version checks also read metadata only. Autosave captures a model snapshot with shared immutable asset objects; the persistence boundary compacts it and reuses unchanged asset hashes through weak references. Neither original input duplicates nor undo history are persisted.

Large photos have a separate 128 MiB LRU of screen-only rasters with a maximum 2048 px edge. Both editor renderers, including image paints on vectors and gradients, use this loader. Geometry and image patterns still use original image coordinates. Export entry points retain the full-resolution loader. Deleted assets and project switches prune preview references, without resetting canvases still used by an in-flight paint. The warnings UI is rebuilt only when its content or its host button changes; text measurement reuses a dedicated context.

## Carousel rotations, folders and effects

`angle` rotates an object around its stored local origin; the rotation handle compensates its origin to rotate around the visible selection centre. Exact cubic extrema determine world bounds, while the single-object frame follows tight local bounds and rotates with the object. Geometry caches use weak object keys and exclude translations. Shift move snapping adjusts distance on the constrained 45-degree ray; Ctrl/Command temporarily bypass snapping. Rotation snapping uses 15-degree steps.

Folders are optional document metadata in `carousel.folders`; members refer to a `folderId` and remain ordinary asset-bearing objects in the flat paint order. Folder members stay contiguous. Folder visibility/locking is inherited rather than rewriting each member. Protected logos stay at the top and outside folders. PSD emits matching groups. A custom carousel logo uses the existing `logos` collection and reference traversal; unused replacements are removed from browser/MKW saves. New brand logos are 600 px wide, constrained only if the available safe area is narrower. Existing dimensions remain intact.

`effects` stores only blur/noise parameters. Local raster caching excludes position, rotation and opacity; a 64 MiB LRU is pruned on deletion and project switches. Large one-off rasters are not retained. Preview raster resolution follows view scale; exports use original resolution. Monochrome noise uses a deterministic object-ID seed, preserves alpha and applies the same luminance delta to RGB. PNG/JPG/WebP/PDF and PSD composites use the shared renderer. PSD effect layers preserve exact raster appearance; text without effects remains editable, and effect text keeps an additional hidden editable copy.

`uppercase` affects display only. Optional `script` and source-indexed `characterStyles` support superscript without rewriting `text`. Wrapping, canvas, inline editing, PDF selection text and PSD share measured runs. Text edits shift style ranges; undo retains them. Curvature-comb visibility is a device preference, not document content; its SVG overlay never reaches an export. Removed device-library fonts stay embedded in documents that still use them, under a separate project-font option group.

Typography layout is weakly cached per source object, keyed by text, font metrics, wrap width, paragraph/character settings and loaded font status. Position/opacity changes reuse it. Plain text and whole-frame superscript measure one run directly; mixed script splits at style boundaries, never loops over every character for every width query.

The FX button adds effects to selected, unlocked layers. Effect rows live inside the layer card; `blurEnabled` / `noiseEnabled` default to true for old documents, and disabling them preserves strengths without changing layer visibility. Source parameters, not generated rasters, are saved. Superscript shifts a measured font baseline by 30% of the original size; the smaller glyph is 65% of that size. Baseline and text-layout caches account for font readiness.

Layer cards keep the selection, visibility and lock controls immediately available, with additional actions in a menu. Folders offer cancel / retain content / delete content; deletion remains undoable and follows asset pruning. The curvature toggle stays available throughout advanced carousel editing, while its comb/band is limited to selected paths. Analytical curvature includes segment endpoints and a shared display scale, so tangent-continuous curvature jumps remain visible. This is a diagnostic display, not automatic G2 handle snapping. Reference behaviour: https://www.affinity.studio/blog/blend-tool-mask-tool-3d-model-support .

Folder `colour` is optional hexadecimal document metadata, assigned automatically from the least-used palette colours. Existing folders without a label receive one when their layer tree is first shown; opening old files remains supported. Colours are stored on folders, so member moves and deletion cannot shift the labels of other folders. Folder headers, member cards and effect branches share the colour; artwork rendering never uses it.

Shift+W shares the footer grid/safe-zone toggle in both editors. The shared capture listener precedes the carousel plain-W angle shortcut, ignores repeats, text entry, open dialogs/popovers and command modifiers, and never changes document content.

Folder drag/drop reorders whole root blocks; children retain their internal paint order and coordinates. Empty folders store an optional `before` root key, resolved without recursion or invalid-anchor loops, so their visual position can survive MKW saves even without paint objects. Receiving the first member restores the empty folder position. Protected logos remain above all blocks; locked folders or locked members cannot be reordered.

Photo-frame effects process the unmasked image, then reapply the original crop polygon (including angle frames). Gaussian blur clamps source edge samples and final output remains inside the real image footprint; it cannot manufacture coverage for an undersized or displaced photo. Angle glow is composited separately from photo effects. Coverage warnings compare frame vertices against the image footprint in local coordinates, without pixel readbacks; intentional PNG transparency is not treated as missing coverage. These warnings remain editor-only.

Cmd/Ctrl+1 and Cmd/Ctrl+0 share editor zoom/fit actions; modal dialogs and paint/effect popovers keep their own shortcuts. Large carousel zoom separates CSS display size from bounded preview raster resolution (24 MP / 16,000 px edge), allowing 100% display of wide artwork without allocating an unbounded canvas. Export resolution stays independent.

The static `hilfe/` wiki opens in a lazily created dialog/iframe from the header or start screen. No wiki document, styles, scripts or iframe are loaded/created at startup. The small `help-popup.js` launcher creates them only after an explicit click and reuses the loaded handbook. Same-origin embedding shares the chosen theme; Escape works inside the iframe and returns focus to the invoking link. Handbook HTML/CSS/JS receive content cache keys during the build. It is readable without JavaScript and adds local text search progressively. Single-post heading `uppercase` is a reversible per-board display flag (true for new and migrated boards). Original text and date inference remain independent; shared layout drives canvas/PSD and the inline editor applies the same text transform. Sponsor strips are available in single posts.

`studioOpenColourPicker` is the callback adapter for opaque hex fields. `colour-inputs.js` delegates existing colour inputs in both editors and settings to the same singleton paint-picker DOM, HSV logic and keyboard controls. Callers supply mutation, validity and placement callbacks. Unsupported gradient/image/alpha controls remain disabled/hidden for opaque fields; no new paint semantics are silently introduced. The singleton is hosted by a modal owner when necessary and shown in the top layer.

Sponsor assets reuse the existing project `logos` collection, tagged `purpose: sponsor`. Board sponsor groups contain only metadata/IDs; reference traversal includes hidden groups and requires Replica LL for group labels. Removing a group from a project releases its unreferenced logo pixels; undo snapshots retain them. The separate device library (`mkw-studio-sponsors`) owns editable templates and cropped lossless logo PNGs, with garbage collection on library changes; changing that library never rewrites an existing project. Settings load only small thumbnails, and template assets are loaded when added to a project. `sponsor-model.js` is pure geometry/validation/contrast logic, `sponsor-library.js` owns IndexedDB, and `sponsor-import.js` owns one-time raster analysis. Optical weights, bounds, colour complexity and centroids are computed once during import; grayscale/monochrome rasters use a non-persistent 32 MiB LRU. All export formats use the shared strip renderer. PSD sponsor strips are labelled raster layers; the photo gets a rectangular design-area vector mask.

Sponsor sizing uses one shared optical ink-area target across all groups, including aspect ratio and density; groups never set their own relative logo weight. Bounded physical height/width constraints and explicit manual scales take precedence for extreme proportions. Import records normalized visible-ink bounds after matte removal, so each group label aligns to the first visible logo edge rather than transparent padding. Canvas label drawing compensates the initial glyph side bearing. No pixel scanning occurs during layout or dragging.

`sponsor-order.js` binds native desktop drag/drop plus Alt+arrow keyboard reordering in the device library. Pure `moveLogo` updates only metadata arrays and preserves asset identity. Cross-group moves commit once on drop, never during pointer movement; project template refresh preserves manual mode/scale by logo ID across groups.

The single-post `sponsors` tool owns strip/groups/logo controls independently from the brand-logo tool. The Options menu contains three text toggles, family mode, sponsor-strip visibility and an optional photo angle with three directions; family palette controls live in the text inspector. Portrait bottom safety is `max(100, originalBottom - stripHeight)` within the reduced content area; square/landscape retain the original bottom inset. Stored format safety values are never rewritten.

`sponsor-pixels.js` performs conservative uniform-matte detection from four sampled edges, tolerating JPEG noise and removing matching enclosed background regions. Transparent silhouettes, swatches and nonuniform backgrounds remain untouched. This bounded analysis runs only on import or the explicit background-repair action. Prepared PNGs store the separated alpha, so monochrome paint never colours an opaque matte rectangle. Legacy light/dark-matte rendering remains readable. Binary black/white logos follow automatic strip contrast; real grayscale and complex artwork retain grayscale detail. Background repair creates a new asset ID and checkpoints before replacement; stale async results are discarded and normal asset traversal releases replaced pixels while undo retains them.

The default `sponsorColour` is validated device preference metadata. It initializes only new strip configurations; changing settings never recolours existing project strips or injects the preference into MKW files.

Sponsor override metadata is cloned in undo snapshots, preserving first-image inheritance correctly when an independent sponsor edit is undone.

Undo/redo return their font-registry refresh promise, allowing programmatic callers to wait for a complete refresh before starting an export.

Sponsor rendering uses actual Canvas multiply/screen compositing over the strip colour. Auto chooses multiply on light strips and screen on dark strips, retaining tonal detail for all artwork. Legacy black/white modes remain readable but are not offered in the inspector. Explicit multiply/screen modes retain tonal detail and are validated portable logo modes. `sponsor-pixels.tones` normalizes visible core luminance to absolute endpoints, preserves alpha and uses known matte polarity for light-on-dark source logos. A near-uniform monochrome mark becomes solid ink instead of amplifying JPEG noise; genuine flat gray marks retain their luminance. The existing bounded raster cache includes blend polarity, so changing strip contrast cannot reuse an incorrectly inverted gray raster. Original colours use source-over. Preview, PNG/JPG/WebP, PDF and raster PSD strips share this rendering.

Single-post cards remain expanded at every viewport width. Their thumbnails are non-persistent 460×220 rasters weakly cached by immutable image data, decoded serially through the shared preview loader only within the viewport margin. Generation checks discard stale results on render/project changes. Canvas originals and portable files are unchanged.

Single-post text layouts use a two-entry weak cache per board, keyed by geometry, text styling, sponsor safety, active field and font readiness. Image-only movement does not remeasure text. Paint reuse compares board content and referenced asset data rather than the global revision, so editing one board leaves unaffected boards intact. Overlay geometry and inline warning content are reused until they change. Carousel paints similarly reuse a committed frame during selection, grid or sidebar-only changes, while asset/geometry/font/editing changes invalidate it. Effect rasters include source pixels and loader identity; a screen raster can never substitute for full-resolution export effects.

Sponsor Auto resolves to the same multiply/screen tonal pipeline as explicit modes. Legacy black/white modes remain readable but are not selectable in the UI. Both editor command bars put their warning count directly before Export. Usage explanations live in the static handbook; control labels, contextual values, errors, limitations and destructive-action explanations stay visible.

## Pasteboard preview

`carousel-pasteboard.js` renders only visible objects whose geometric bounds lie entirely outside the combined slide area. Partially overlapping objects remain clipped to the artwork. One viewport-sized raster (at most 4 million pixels) is coalesced and stale paints are discarded; scrolling culls far-away objects. Pasteboard extents grow for off-artwork objects without changing their document coordinates. Extents remain stable during pointer drags and rebalance on release. This screen-only canvas never enters image, PDF, PSD or MKW exports.

## Portable tool setup

`setup-model.js` owns the versioned `mkw-setup` schema and the canonical preference defaults, including per-role text sizes. `setup-session.js` captures device preferences, theme, custom-font library and sponsor groups/assets. It uses `project-file.js`'s shared streaming gzip/JSON codec without project compaction. Unused sponsor assets, duplicate group thumbnails, projects, file handles and history stay out. Reads are bounded to 256 MB after decompression, validate the whole model, verify font identities/loadability and decode PNG logos before any writes.

`setup-store.js` persists a read-only source handle (where supported) or filename metadata plus a temporary rollback journal. Applying a setup replaces the two device libraries transactionally within their existing databases and persists preferences only after validation. Failures restore the previous libraries/preferences/link; unfinished imports are recovered at startup before fonts/projects load. The journal is removed after completion, so it does not retain a second permanent copy of the libraries. Settings UI is disabled during these explicit operations. No source file is opened on startup or written by refresh. Firefox reselects the source file on refresh because it cannot retain local file access.

Existing project objects never receive imported defaults. Used custom fonts and sponsor assets remain project-owned even when absent from a new setup's device libraries. New single-post boards use `preferences.textSizes`; normal first-image template inheritance takes precedence for later images/formats. The setup link is a tool preference and never enters MKW project files.


## Single-post photo angles

`post-angle-model.js` owns optional `board.angle` metadata, validation, oversized chevron geometry, rectangle-clipped vertices and photo coverage. `post-angle.js` adapts the existing carousel angle mask/glow renderer to single posts, owns option inheritance and context controls, and coalesces angle/content drags per animation frame. The same board photo is used directly; no asset ID or pixel duplicate is stored. Both rear ends of the oversized six-sided chevron stay outside the sponsor-reduced content rectangle; the two front vertices remain inside. Content uses an independent image transform and does not rotate on direction changes. Layout/PNG/JPG/WebP and PSD bitmap paint share the same function; PSD labels the angle as raster content. A changed angle does not invalidate other boards' text or photo caches. Overlay elements are reused during dragging. Angle activation and direction affect only boards of the same image. Other images never inherit an angle from the first image. Legacy `angleOverrides` metadata remains readable but no longer controls propagation. New formats of the same image inherit angle settings with a fresh photo crop; old boards without angles remain unchanged.

## Shared advanced typography

`text-model.js` owns pure UTF-16 source-indexed character ranges, partial-attribute patches, adjacent-run normalization, edit shifting, paragraph scopes and validation. `typography-ui.js` owns one shared inspector and transient selection/typing state (weak object keys), with adapters for post elements and carousel objects. Tool preferences never store these document formats. Frame selection targets the whole text; marked ranges target characters; collapsed carets target subsequently typed characters. Paragraph edits target the intersecting paragraphs (exclusive range end). Original text is never rewritten for display case, script, tracking or baseline shift. Normal-mode controls remain available, and turning advanced mode off never removes document formats. Custom cuts are actual font choices, not synthetic bold/italic.

Carousel measured runs carry font, size, display text, colour, tracking, script, baseline offsets and decorations. Line positions include paragraph spacing, per-paragraph leading and existing per-line leading overrides. Canvas uses letterSpacing where supported by the browser; current Chrome and Firefox are validated. Derived layouts are weakly cached and source fonts are included in asset reference traversal, even when used only by a range. Deleted text releases unused persisted fonts; the device font library stays separate.

Single-post `MKWLayout.textLayout` accepts an optional styled-layout callback. Legacy plain elements retain their old geometry. Rich fields reuse the measured carousel runs while preserving common safe-zone autofit, bottom layout, optical title offset and independent vertical copyright. Copyright never changes the main text-gradient height. Family rendering retains its palette/outline and forces copyright to black/white without outlines. Rich post PSD uses a named exact raster plus a disabled group of native text runs; carousel PSD emits native runs. PDF remains exact raster appearance with a separate embedded-font searchable text layer and matching run tracking. Do not claim full editable paragraph-flow interoperability.

Single-post angle movement remains direction-constrained within the sponsor-reduced content rectangle. Carousel angles are freely positioned: no render, restore, numeric edit, rotation, resize or drag-end operation may force their origin/tip back onto an axis or artwork edge. Only a default angle created without an explicit position uses the initial centre/bleed helper; explicit creation rectangles remain exact. Move snapping includes angle tips as offsets within selection bounds, using the same tolerance, bypass controls and Shift ray as ordinary bounds. Tip offsets are captured once per gesture and rotate with the object. Image panning remains independent.

## Single-post side safe zones

Format and board safe zones may store optional `left` and `right` output-pixel values. Absence preserves the legacy 100 × width/1080 margins. `MKWFormats` owns validation, metadata copying and the shared four-side graphic; `post-safezone.js` binds the same graphic in Format anpassen. Invalid drafts never mutate the board. Import, new board creation, resizing, snapshots and MKW round trips preserve explicit margins. Text, logo, overlays and copyright read `MKWLayout.safeRect`. Tool preferences are unaffected. PSD raster contexts use the shared CPU export context. Each post is painted at a local zero origin into one reusable board buffer before composition, avoiding Chrome SVG edge rounding differences caused by painting at translated document coordinates.

## Single-post text stack

`post-text-stack.js` owns the spacing inspector and reusable on-canvas gap controls. `MKWLayout` measures optional `textBox.gaps` by adjacent role pair (`date:title`, `title:subtitle`, `date:subtitle`) in output pixels. Missing entries use the original 8 × width/1080 gap and retain the title's 2.5 px optical correction. Layout, export and PSD use the same records; controls are overlays only. Auto-fit scales text and gaps together. Resizing scales explicit gaps; new formats inherit them without inheriting the text block offset. Whole-block movement must preserve the gap metadata. Changes from the first image follow matching adjacent text pairs; other images remain individually editable. Gap drags are animation-frame coalesced, checkpoint once, and restore on cancellation. No assets or tool preferences are introduced.

## Bounded justification and paragraph size

`text-justify.js` owns pure bounded composition: word spacing 0.8/1/1.2, additional letter spacing -0.02/0/0.02 em, horizontal glyph scale 0.98/1/1.02. `carouselJustifyRuns` measures word/space/style tokens once per candidate; wrapping considers the minimum width, while each paragraph's final line keeps optimal spacing and its natural left origin. Fit prioritizes word spacing, then letter spacing, then glyph width, never silently exceeding limits. Non-fitting lines produce existing artwork notices. Normal alignments bypass this code. `text-hyphen.js` implements Knuth–Liang points using the locally shipped MIT German reformed-2006 TeX patterns, as used by modern Swiss German. Patterns are content-versioned and fetched only when justified text needs hyphenation; compilation yields between 1000-pattern batches and a bounded 1024-word cache avoids repeat work. A shared promise prevents parallel dictionary loads. Paint/export await readiness; weak layout/cache keys include dictionary version. Optional field/paragraph `hyphenate` is document metadata, never a character mark. Original UTF-16 text and range offsets remain unchanged. Candidate line breaks include legal points in words of at least six letters, with two letters each side; virtual dash runs have zero source length, and inline editors draw them using an empty non-editable pseudo-element. Rendering and PDF/PSD use identical measured dash runs. No dictionary pixels/data are saved into MKW files.

Shared measured token x positions, tracking and glyph scales drive canvas, raw-source-preserving inline spans, PNG/JPG/WebP, PDF pages and searchable PDF text. PSD keeps a faithful raster plus hidden editable word runs for justified frames. Selected paragraph `textStyles[].size` is exposed in both advanced inspectors, with mixed values, range scope and reset to field size. Single-post notices measure paragraph layout only for objects actually using justification, avoiding work for ordinary image projects.

Sponsor automatic mode selects multiply/screen only. Legacy black/white document modes remain readable but are not exposed in the current UI.

Single-post typography size propagation is format-specific: `setSharedTextSize`, selected-character sizes, paragraph sizes and pending typing styles follow only equal output width/height when changed on the first image and the text matches. ## Stable direct text input

`inline-text.js` owns shared input-only run positioning, cached DOM baseline measurement and one-frame viewport focus protection. Regular editing keeps the original canvas text visible, including family colours/outlines, opacity, blend and effects; the transparent contenteditable carries source text, selection and the caret at the measured positions. This avoids browser-native wrapping or font line-box metrics replacing the final artwork. Focusing must never set `typographyVersion` or modify document styles. Plain legacy post fields derive input runs without converting stored typography. The line/paragraph source offsets, discretionary hyphens and raw copy/paste semantics remain unchanged. IME pre-edit temporarily displays the DOM input and excludes only that text from the preview; committed text returns to the shared renderer. Entering/leaving regular text input no longer invalidates full artwork paint caches. Native input that bypasses beforeinput records a local undo snapshot before applying its change.

Sponsor geometry uses the existing dark-on-light density as a fixed reference for automatic, multiply/screen, grayscale and original modes. Changing strip brightness must not change logo bounds, spacing, group wrapping, strip thickness or safe-zone content bounds. Rendering still changes polarity/compositing normally. Legacy solid black/white modes retain their original density baseline; manual scales remain metadata multipliers. No source pixels are read or converted during layout.


## Inspector and validation boundaries

`studio.js` owns the single-post session integration; `MKWPostInspector.create({read, actions, views})` owns inspector rendering and binding. It reads one fresh state snapshot when rendering, passes selection changes through a command and binds controls inside the inspector panel. Crop, simple text and logo controls are private tool handlers. Advanced typography, sponsor controls, angle controls and text-stack controls remain their existing services. Do not reach directly into `p`, `layer`, `step`, preferences or editor globals from the inspector module. Existing global `renderPanel` is a compatibility adapter, not a second implementation.

`MKWProjectValidation.create` takes explicit model validators. It can validate portable documents without loading a DOM, UI, image decoder or editor session. Keep restoration and mutation in the session layer. New document validators belong in this service's injected dependency list, not in implicit UI globals.

`MKWCarouselPolicy` defines an inclusive range of 1–20 integer slides across setup, validation and add/delete/duplicate controls. The last slide cannot be removed. Per-page image/PDF exports retain the same limits; PSD retains its independent total-pixel/dimension limits.

`MKWCarouselPolicy.safeRect/grid` defines the per-slide safe rectangle and its sixths from all four document margins. Setup previews, viewport guides, snapping and text warnings use those margins consistently. Guides remain view-only. Path continuation keeps world-space draft points and a source identity; reversing swaps incoming/outgoing controls and endpoint decorations. Joining commits once, retains the source layer's style/identity/paint placement, and removes the consumed path through normal asset pruning. Cancellation leaves source objects untouched. Only clicking the draft's first anchor closes a path; snapped proximity never closes it.

Designer grid columns/rows (1–24) and a shared gutter (0–500 output px) belong to tool preferences and MKW-Setup, never project snapshots. The default remains sixths without gutters. `MKWCarouselPolicy.grid` clamps oversize gutters to the available safe rectangle and supplies both gutter edges to snapping; `MKWDesignerGrid` uses the same cell/gap proportions in CSS previews without adding per-cell DOM or raster work. The slide format inspector edits a local draft, validates through `formatPlan`, then applies all six document fields and export board dimensions in one checkpoint. Width changes rebase object origins to the new slide origins without resizing/reflowing elements; objects wholly to the right retain their distance from the artwork edge. Safezone-only changes leave all object geometry untouched. Existing projects and locked objects never change when a grid preference changes.

New angle directions are up/left/down in both editors. `MKWAnglePolicy` keeps legacy right-facing saved objects readable without mirroring or moving an existing design; only such objects expose a labelled legacy right choice. Left-facing geometry mirrors the clipping mask only, never the photo transform. Single-post left angles remain centred vertically and move only horizontally; carousel left angles remain freely movable/rotatable with ordinary snapping.
